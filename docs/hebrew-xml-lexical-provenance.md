candidate milestone. No production shards are generated by this work.

## Component notices and lineage

In the pinned XML, lines 26–38 declare the `Strong` work: James Strong,
Hunt & Eaton, **original edition 1894**, electronic version 2009.06.22, editors
David Troidl and David Instone-Brewer, and `Public Domain`. The description says
the data came from several public-domain sources, cleaned by comparison and
consulting the original. This is the positive component-specific rights evidence
for the whitelist below. It is not a public-domain declaration for the whole XML.
The generic project description “Strong's 1890 dictionary” must not replace the
XML's actual edition metadata.

Lines 49–56 separately identify TWOT (1980, Moody, ISBN 0802486495), with an
explicit copyright notice. Lines 58–60 assign `//w/@ID` and `//w/@src` to Strong,
and `//w/@gloss` to TWOT. TWOT-linked values are excluded, even though they often
look like harmless numeric cross-reference keys. No TWOT prose or unassigned
numbered-list prose is copied into the tests or adapter output.

The XML revisions credit conversion to XML (2008.03.18), Greek reference markup
(2009.06.22), Unicode transliterations, vowel/correction work (2010.04.02), typo
notes (2010.04.04), and whitespace (2010.05.24). Retained ancestor commits include:

- `66fb7e7abddc736fce51ec7d05ea29768dcd5ebe`: Troidl's Unicode transliteration
  and correction work, while retaining the Strong work's public-domain notice.
- `2f816226d4641014c7fce5452b1ca0be59047f2c`: JSON conversion added.
- `af921223a547612b6b112baf5359d12fbb6659c7`: XML/XSLT whitespace changes.

- `35fcf2f61181a0783fb405561cbc9eb6f2f4b347`: 2018 additions to translation
  notes H2579/H5617/H5960/H7893; these notes are outside the whitelist.

The retained `hebrew/StrongJson.xslt` supplies field semantics: lines 31–40 emit
ID, lemma, xlit, and **pron from POS**; lines 57–65 emit explanation as
`strongs_def`, with inline `hi` text. Lines 43–55 separately emit exegesis as
derivation; lines 67–70 emit translation as `kjv_def`. Lines 73–80 explicitly
discard foreign/list/item. The stylesheet is transformation evidence, not an
independent license grant or proof that every unassigned field is Strong's text.

The compiled Hebrew JavaScript header separately says Copyright 2010 Open

That output is not selected or executed, and its output notice is not silently
transferred to every XML component or silently ignored to republish the JS.

Michael Grier's public-domain e-text is explicitly credited in the **DAT**

## Field-by-field decision

Paths below are relative to a direct glossary `div[@type='entry']` under the
Strong work. “Reviewed allowed” rests on the **Strong-specific public-domain
header plus the retained XSLT's semantic assignment**, including the credited
electronic editing. The independent review found this evidence sufficient for the exact subset, not for any other XML field.
The retained evidence cannot identify the individual editor of every correction.

| XML field | Contract use | Provenance and decision |
| --- | --- | --- |
| Direct `w/@ID`, entry `@n` | `strongsNumber` | Reviewed allowed: Strong identifier, explicitly assigned by workPrefix; `@n` only cross-checks its number. |
| Direct `w/@lemma` | `lemma` | Reviewed allowed: Strong headword under the PD Strong work; Troidl/Instone-Brewer electronic editing applies. Do not claim an untouched 1890 transcription. |
| Direct `w/@xlit` | `transliteration` | Reviewed allowed: Strong transliteration, with explicitly credited Troidl Unicode conversion/corrections; XSLT emits xlit. |
| Direct `w/@POS` | `pronunciation` | Reviewed allowed: Strong pronunciation respelling, confirmed by XSLT's `pron` mapping. Despite its name this is **not** part of speech. |
| Direct `note[@type='explanation']`, text and plain `hi` | `definition` | Reviewed allowed: Strong definition under the PD Strong work; XSLT explicitly names it `strongs_def`. No fallback to any other note/list. |
| Any `w/@gloss` | None | Excluded: explicitly TWOT-linked copyrighted component. |
| `list/item` text | None | Excluded: provenance not individually established by the retained notices; the XSLT also discards it. Do not guess that it is PD, TWOT, or BDB. |
| `foreign`, nested Greek `w/@gloss` | None | Excluded: cross-reference material, not needed; workPrefix also associates gloss with TWOT despite Greek-looking values. |
| `note[@type='exegesis']`, nested `w/@src`, lemma/xlit/POS | None | Strong derivation/cross-references, with embedded editorial corrections; not needed. Even Strong-assigned src does not license copying the whole mixed subtree. |
| `note[@type='translation']` | None | Strong/KJV renderings plus later additions; excluded rather than treating as an alternate definition. |
| `note[@type='x-typo']`, `catchWord` | None | Troidl/editorial annotation material, including nested corrections; excluded from projected definitions. |
| Direct `w` text | None | Unpointed lexical spelling; excluded. OSHB supplies actual token surface. |
| `w/@morph`, `w/@xml:lang` | None | Dictionary grammatical/language metadata, not contextual OSHB token morphology. Excluded; not a basis for token Hebrew/Aramaic classification. |
| Header/revision/work metadata, namespace/schema URI | Review evidence only | Retain notices, edition, identities and hashes in this report; do not concatenate into definitions or fetch schemas. |

The other ten contract fields are outside this lexicon: `status`, `source`,
`language`, `morphology`, `partOfSpeech`, `bookId`, `chapter`, `verse`, `tokenIndex`,
and `surface`. Publication status and attribution need reviewed configuration;
coordinates and surface come from the mapped OSHB text; language/morphology and
any contextual part of speech come from OSHB morphology. This adapter invents no
English alignment, classification or source values. For numeric IDs, the XML strategy supplies the lexical headword in `lemma` and
fills transliteration, pronunciation and definition. Original OSHB lemma
annotations are preserved in `diagnostics.sourceLemmas` at source coordinates.
The 310 grammatical words without numeric IDs retain OSHB lemmas and null
lexical fields. Source surface, morphology and language detection stay unchanged;
`partOfSpeech` remains null. No new record field is added.

Lexical attribution selected by the reviewed Isaiah configuration:
“James Strong, A Concise Dictionary of the Words in the Hebrew Bible, Hunt & Eaton,
1894; electronic editing by David Instone-Brewer and David Troidl; Strong work
declared public domain in Open Scriptures StrongHebrewG.xml; selected Strong
fields only; revision 0acd2f251c2d35ff8db2dece4e0593979d3ac223.”
OSHB/WLC notices must still accompany the separate token source.

## Complete structural audit

All 8,674 entries (H1–H8674) have one direct `w`, with nonempty ID, lemma, xlit,
POS, morph and xml:lang, and one nonempty direct explanation. All explanations
contain only text and 14,545 plain, attribute-free `hi` elements. No explanation
contains a cross-reference, list, foreign word, or editorial annotation.

Excluded structures: 6,070 direct gloss attributes; 8,674 lists with 24,841 items;
3,686 foreign containers with 14,120 word references; 8,670 exegesis notes;
8,674 translation notes; and 217 typo notes (124 direct, 90 in exegesis, three in
translation). Exegesis contains 8,775 `w` elements, translation 336. Direct
dictionary language labels are 5,393 heb, 653 arc and 2,628 x-pn; these are not
Isaiah token counts and are never projected.

The review adapter produces 8,674 complete five-field lexical entries, and two
runs produce identical values and ordering. All 2,443 distinct numeric Strong's
IDs in the existing Isaiah dry validation join: zero missing IDs. These joins are
also validated through the new generic strategy. This does not
authorize shard publication. The normal Isaiah dry validator reads only XML;
DAT is available solely in an explicit historical comparison tool.

## Adapter boundary and review gate

`tools/strong-hebrew-xml-lexicon.js` has no writer. `loadReviewLexicon(path)` and
`parsePinnedLexicon(bytes)` accept only the pinned XML fingerprints, verify all
8,674 identifiers, and return a five-field Map, artifact/revision/hash metadata,
`reviewStatus: 'field-subset-reviewed'` and `publicationEligible: false`. The
separately exported structural parser supports adversarial unit fixtures; parsing
arbitrary text returns `structural-only` status without claiming a pinned revision
and does not authenticate it. Configured generation additionally
requires the exact configured lexical fingerprint, even during dry validation.

The limited OSIS scanner rejects DTDs, custom entities, external resources,
unsupported markup and namespace changes. Projection uses direct children and
explicit attribute/node allowlists, including ancestors that could override
provenance. It rejects duplicate IDs, unknown structures affecting selected
fields, extra lexical attributes and mixed explanation markup. Missing selected
fields report the ID and field explicitly; no other note/list/surface supplies a
fallback. Only standard/numeric XML entities and whitespace are normalized;
Unicode is not normalized. Excluded subtrees are structurally parsed but their
values never enter selected fields or diagnostics. No eval or new dependency is
used. DAT parser semantics are unchanged.

Adversarial tests mutate/remove excluded fields, inject nested lexical fields,
shadow fields through unknown ancestors, change provenance/namespace declarations,
and supply missing or mixed lexical records. Full local checks cover pinned
hashes, all entries, H1/H65, every Isaiah join, deterministic output, no DAT
fallback and blocked writers. Synthetic fixtures contain no retained TWOT or
unassigned-list prose. Local tests skip explicitly when inputs are unavailable.

Review conclusion: each accepted field has the exact selector documented above,
component-specific Strong PD evidence, and retained XSLT semantics; every excluded
component is unreachable through projection or fallback. Michael Grier ancestry
is unestablished for XML and is not claimed. The compiled JS's CC-BY-SA notice
and the DAT's contradictory notices do not license the whole XML. A separately
authorized publication-candidate milestone must still perform fresh staging,
complete deterministic regeneration and focused validation before enabling
publication. The old DAT remains license-unresolved and publication-ineligible.

The [complete comparison report](isaiah-lexical-comparison.json) contains all
2,443 used numeric IDs, occurrence counts, exact UTF-8 hashes and byte lengths for
each old/new definition. All 2,443 definitions differ (16,622 token occurrences).
The XML uses only explanation notes, rather than the DAT parser's complete
flattened entry text; it also adds headwords/transliterations/pronunciations for
those occurrences. Attribution changes on all 16,932 dry records. Every other
record field is equal (169,320 field values), including Strong IDs, mapped
coordinates, token indexes, source surface, morphology, language and status.
Historical DAT prose is not copied into this report. It is an explicit audit
comparison, not a second selectable Isaiah source or a fallback.

## Reproduce the audit checks

From the repository, with the already-local package at the recorded root (or
`GOD4_ORIGINAL_LANGUAGE_SOURCES` pointing to it):

```powershell
node --test tests/strong-hebrew-xml-lexicon.unit.js
node tools/validate-isaiah-original-language.js
node tools/compare-isaiah-lexical-sources.js
```

The normal validator uses XML only. The comparison command explicitly also
requires the pinned historical DAT and writes a deterministic report to stdout,
never shards. `serializeComparison(compareLocalIsaiah())` reproduces the committed
comparison report bytes (LF). No full Isaiah generation command belongs to this
milestone.
